## 一、Codex

### 1. Codex CLI 0.166.0（80/100）

**官方发布时间：** 2026-10-29 19:47 UTC（GitHub 发布记录 `published_at`）；learn.chatgpt.com 更新日志标注 2026-10-29

**北京时间：** 2026-10-30 03:47 · 已确认在窗口内

**是否调整用法：可以关注**

**变化内容：**

1. 转录内容支持键盘选择，可按词、行、页移动，集成搜索，快捷键可配置。
2. 异步提问、选项、回答和转录回复统一按 Markdown 渲染。
3. 内置、Vertex AI 和 Amazon Bedrock 模型目录加入 GPT-6.1 Terra。
4. 新增 `codex queue --resume`：排队一条消息后，可以恢复已卸载的会话。

8. 构建：Bazel 改用源码构建的 V8；发布包附带独立 executor；开发和发布构建统一到 Node.js 24.22.1 和 Rust 1.95.0。

**推荐理由：**

用 Codex CLI 的值得升级。恢复/fork 会话保留权限、推理 token 计数不再丢失，这两项修复对长会话影响直接；网络有问题时可以先跑 `codex doctor --network-only`。

## 二、ChatGPT

### 1. 新版模型规范（Model Spec）（70/100）

**官方发布时间：** OpenAI 官方 RSS（openai.com/news/rss.xml）`pubDate` 为 2026-10-29 17:00 GMT；文章页只标注 10 月 29 日

**北京时间：** 2026-10-30 01:00 · 已确认在窗口内

**是否调整用法：可以关注**

**变化内容：**

OpenAI 更新了模型规范，把指导原则围绕五项基本价值观重新组织：忠于人类意图、尽量减少伤害、诚实与透明、人的自主性、关怀。新增“忠于人类意图”一节，纳入更新后的指令层级，说明哪些指令适用、指令冲突怎么解决；新增“审慎考虑上下文”小节，说明模型如何根据对话、记忆等上下文理解意图和偏好；新增支持人的自主性、遵循相关社会规范的默认规则，扩充了控制和说明附带影响的指导。

同时移除了大部分细化的风格指导，风格改为适应用户偏好；保留“客观看待问题”等约束更强的默认规则。规范中改用“GPT”而不是“助手”指代模型。OpenAI 说明目前的模型尚未完全达到规范要求，并在探索新的训练方法。

**推荐理由：**

规范决定模型的默认行为。风格指导大部分移除后，想要特定风格最好在指令里写明；做应用的开发者可以看一下新的指令层级。

**官方原文：** [An updated Model Spec for more capable and beneficial AI](https://openai.com/index/updated-model-spec)

### 2. 社区安全报告与青少年新保护措施（62/100）

**官方发布时间：** OpenAI 官方 RSS `pubDate` 为 2026-10-30 09:00 GMT；文章页只标注 10 月 30 日

**北京时间：** 2026-10-30 17:00 · 已确认在窗口内

**是否调整用法：可以关注**

**变化内容：**

1. OpenAI 承诺发布社区安全报告，首份在 2027 年初发布，覆盖 2026 年下半年，之后每六个月更新一次。2026 年第三季度向执法部门转介超过 200 次。

3. 近期对话出现暴力预警信号时，ChatGPT 在分享可能被滥用的信息时会更保守；对话显示有人执着于暴力或严重伤害他人时，ChatGPT 将能自动结束对话，多次因此结束对话的账号可能被暂停。

5. 正在开发通知功能：青少年账号因反复讨论暴力被暂停时通知家长。

**推荐理由：**

属于安全策略调整，普通使用不受影响；被误判为未成年的成年用户可以走 Persona 验证。

## 三、Claude（含 Claude Code）

### 1. Claude Code v2.1.314（88/100）

**官方发布时间：** 2026-10-30 01:06 UTC（GitHub 发布记录 `published_at`）

**北京时间：** 2026-10-30 09:06 · 已确认在窗口内

**是否调整用法：需要（脚本调用 `claude -p`、管理员限制 effort、用网关或 Bedrock 的场景）**

**变化内容：**

1. 新增 `permissions.blockWritesOutsideWorkingDirectories`：开启后，Write、Edit、NotebookEdit 在任何权限模式下都拒绝写工作目录以外的路径。
2. Claude apps gateway：上游可配置 `groups`，只把指定 IdP 组的开发者发往该上游（故障切换时同样生效）；Bedrock 上游新增 `guardrail_trace`，记录是哪个 Bedrock guardrail 过滤器触发（不记录匹配文本）。
3. VS Code 和 Claude Desktop 的 Code 标签页新增闲置压缩：20 万 token 以上的对话闲置后会被摘要，提示缓存过期时下一条消息使用摘要。
4. 修复：组织管理员限制模型 effort 时，会话不再每轮报 “Invalid effort level”，改为自动降低 effort 重试并说明所用级别；`claude -p` 启动失败时不再以退出码 0 无输出退出，改为打印错误并退出 1；Bedrock 会话图片多时不再每轮报 “400 Input is too long.”；Microsoft Foundry 资源缺少默认模型部署时回退到同系列旧模型；修复系统证书库含交叉签名的续期根证书时 TLS 报 `UNABLE_TO_GET_ISSUER_CERT`；`claude -p --resume`/`--continue` 进入的 worktree 现在应用沙箱保护；Monitor 工具启动的 shell 命令也会触发匹配 Bash 的 hook；“用量上限时自动继续”不再在任务自行重启时超过三次。
5. 改进：大量子代理的无头和 SDK 长轮次内存占用降低；Ctrl+R 历史搜索可以匹配折叠的 `[Pasted text]` 内容；auto mode 被拦截时提示更清楚；`--resume` 处理损坏转录更快。
6. 变更：Claude 的文件工具编辑组织服务端托管设置的本地副本前会先询问；`/ultrareview` 运行 git 前先检查工作区信任；`FORCE_HYPERLINK=false`（以及 `no`、`off`）现在是关闭超链接；Bash 工具的 shell 会清除继承的 `which` 别名或函数。
7. VS Code 扩展、云端会话、Remote Control、Claude Tag 也有多项修复和改进。

**推荐理由：**

在脚本或 CI 里用 `claude -p` 的，以前启动失败可能被当成成功，这版必须升级；需要限制写入范围的可以开新权限项。注意 `FORCE_HYPERLINK=false` 的含义反过来了。

**官方原文：** [Claude Code v2.1.314 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.314)
