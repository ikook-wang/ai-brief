## 三、Claude（含 Claude Code）

### 1. Claude Code v2.1.319：自动模式、MCP 后台任务与权限行为调整（90/100）

**官方发布时间：** 2026-11-06 17:04:01 UTC（GitHub 发布记录 `published_at`）。

**北京时间：** 2026-11-07 01:04:01 · 已确认在窗口内；网页时间显示为 01:04。

**是否调整用法：需要**

**变化内容：**

1. **自动模式的检查方式有变化。** 关闭遥测或功能标志时（包括通过 LLM gateway 的情况），服务器不能检查的工具调用会询问或拒绝，不再回退到内置分类器；设置 `CLAUDE_CODE_AUTO_MODE_SERVER=0` 可继续使用内置分类器。Bedrock、Vertex 和 Foundry 不受这项变化影响。通过 gateway 时，`CLAUDE_CODE_AUTO_MODE_SERVER=1` 即使配合 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` 也会开启服务器检查；若后者由受管配置设置，前者也须由受管配置设置。
2. **终端支持 MCP tasks。** MCP 服务器以任务方式执行工具调用时，Claude Code 会立即转到后台，完成后再把结果交给 Claude；设置 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` 可改为在工具调用内等待。MCP tasks 不再依赖功能标志拉取，也可在 Bedrock、Vertex、Foundry、gateway 或关闭遥测时工作；`CLAUDE_CODE_DISABLE_MCP_TASKS=1` 可关闭。
3. **新增拒绝等待权限提示的设置。** `permissions.denyInsteadOfPrompting` 会拒绝原本要等待权限确认的工具调用，并继续当前轮次，适用于终端、子代理和队友。
4. **非交互脚本的失败信号更明确。** `claude -p` 在自动模式因没有可用检查而拒绝操作时，text 和 JSON 输出现在以 1 退出；`claude -p --resume` 遇到缺少 MCP 服务器的待执行工具调用时，也以 1 退出、保留该调用并拒绝后续输入。修复了多项登录重试、磁盘写满和配置保存问题。
5. **后台任务和上下文处理改进。** `/tasks` 增加已完成子代理入口，离开列表或重启后仍能重新打开并发消息；修复旧 MCP 握手、恢复会话后长调用不返回、极快结束的后台 Bash 丢失输出，以及 `/clear` 杀死本应继续运行的任务。`/context` 给 Claude 的表格只保留每类最大的 10 行，按需加载的 MCP 工具在调用前合并为一行。
6. **定时循环、代理与证书配置有变化。** self-paced `/loop` 在一轮结束且没有重新调度时结束，不再自动兜底唤醒；`CLAUDE_CODE_LOOP_KEEPALIVE=1` 可保留旧行为。只设置 `ALL_PROXY` 时不再触发 TLS 检查代理的自动证书修复，需要按发布说明设置 `HTTPS_PROXY`。
7. **权限与安全修复。** 修复带引号的 Bash 规则漏匹配、特定 `sed` 命令与环境变量前缀绕过权限检查、通过目录符号链接恢复文件、创建 worktree 时逃逸沙箱等问题；还收紧了 Monitor、嵌套技能加载和新增目录的信任行为。
8. **其他新增与修复。** `/claude-api latency-optimize` 可分析 API 代码的等待并对照评估尝试更快设置；新增独立关闭功能标志拉取的 `CLAUDE_CODE_DISABLE_FEATURE_FLAGS`。Claude apps gateway、VS Code、云端会话、Remote Control、自托管 runner 和 Claude Tag 也有多项改进，完整细目见官方发布记录。

**推荐理由：** 自动模式与 MCP 任务的默认行为改变，依赖 `claude -p` 退出码、`/loop` 或代理配置的日常流程需要核对；新增权限选项及多项权限、安全修复也值得使用者检查。

**官方原文：** [Claude Code v2.1.319 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.319)
